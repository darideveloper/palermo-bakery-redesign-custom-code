## 4. Convert the lightbox .ppt to a permalink link

Implementation note: the design said `image-lightbox.js`, but the actual lightbox machinery (MutationObservers, button injection, product ID capture) lives in `fav-button.js`. The implementation lives there, hooked into the existing `injectLightboxFavBtn` flow.

- [x] 4.1 On page load, build a `productId → permalink` map by scanning all `a[data-product-permalink]` on the page. The map is rebuilt on gallery grid re-render (category filter) and on favorites grid re-render (AJAX). It is empty on pages with no such anchors.
- [x] 4.2 In `src/features/favorites/fav-button.js`, hook into the existing lightbox image MutationObserver (the same one that updates the fav button on prev/next) to also call `convertPptToLink(img.src, currentLightboxProductId)`. On every lightbox open and every image change, the `.ppt` element is converted to `<a target="_blank" href="<permalink>">` if a permalink can be resolved, otherwise it remains as plain text. The function is idempotent.
- [x] 4.3 The resolution order is: (a) match the current lightbox image's `src` (stripped of query string) to an `a[data-product-permalink]` on the page, (b) look up `currentLightboxProductId` in the `productId → permalink` map, (c) return null and leave `.ppt` as plain text. The implementation does not emit anchors with empty or `#` href.
- [x] 4.4 The existing fav button, share button, prev/next arrow navigation, and lightbox open/close lifecycle are unchanged. `convertPptToLink` only touches the `.ppt` element; it does not modify the fav button, the share button, the button row, or the `<img>` itself.
- [x] 4.5 (Verification follow-up) Gated `buildPermalinkMap()` to run only on `/cake-gallery/` (URL-path check) per the user-confirmed design decision and the spec's "Map is empty on non-`/cake-gallery/` pages" scenario. On the favorites page, the map stays empty and resolution falls through to the image-src match path (which works because the favorites anchor's `href` matches the lightbox image's `src` and the anchor carries `data-product-permalink`). The selector is now strictly `a.product-image[data-product-permalink]`, matching the spec's wording.

## 7. Prod-sync notes (maintainer-facing)

Three prod fixes were backported into `src/core/functions.php` to close gaps vs. `src/core/functions_prod.php`. The mirror is the maintainer's responsibility (per `AGENTS.md`); these notes explain what changed and what to skip.

- [x] 7.1 (A1) Cupcake contact popup responsive CSS — added. Compacts `#custom-popup-wrapper #popup-form-container` for `@media (max-width:600px)` (phones), `@media (min-width:601px)` (desktop panel sizing), `@media (min-width:601px) and (max-height:820px)` (small laptops), `@media (min-width:601px) and (max-height:700px)` (drop intro helper), and a plain z-index lift when the popup is open. Inserted after the `.page-id-1109` mobile rule in `snsvicky_cssinline()`. No risk — purely additive CSS targeting a single wrapper.
- [x] 7.2 (A2) Rogue-script regex hardened — the lazy `[\s\S]*?` body matcher is replaced with an unrolled `[^<]*(?:<(?!\/script\b)[^<]*)*` loop, and the callback result is captured to `$stripped` with a `null` guard before assigning to `$buffer`. Without this, large inline scripts (e.g. `yith_wcwl_l10n` on the full shop loop) hit `pcre.backtrack_limit` (1M) and `preg_replace_callback` returns `null`, blanking the page.
- [x] 7.3 (A2b) Same null-guard pattern applied to the `<img>` rewrite callback (`$rewritten`). The `<img>` rewrite isn't known to crash today, but the pattern is identical to A2 and worth keeping for symmetry.
- [x] 7.4 (A3) `null` guard on the reCAPTCHA-stripping regex in the iOS-fix block — same pattern. Captures to `$stripped`, returns `$stripped !== null ? $stripped : $buffer`.
- [x] 7.5 (YITH pre-pass bugfix) Replaced the per-YITH window-walking pre-pass with a per-card regex matching the theme's real card wrapper. **Three-stage fix:**
  - (a) The original implementation mutated `$buffer` by reference (`use (&$buffer)`) inside `preg_replace_callback` and then re-assigned the result to `$buffer` — the reference mutation is discarded when the return value is re-assigned, so **no `data-product-permalink` was ever emitted** (verified via a local PHP harness: 0/5 attributes with the old code).
  - (b) The first per-card attempt targeted WooCommerce's default `<li class="product">` wrapper, but the SNS Vicky theme wraps each card in `<div class="… post-{ID} product type-product …">`. The `<li>` regex never matched → 0 attributes on the live site → the lightbox `.ppt` stayed plain text. Fixed to anchor on the stable `post-{ID}` token in the wrapper class.
  - (c) The lazy `.*?(?=…|$)` body matcher in the per-card regex exhausted `pcre.backtrack_limit` (1M) on the full shop archive (349 products). The `yith_wcwl_l10n` footer script scales to ~1.1MB on the full catalog; the lazy scan from the last card to end-of-buffer counted 1.1M+ backtrack steps, `preg_replace_callback` returned `null`, and the assignment was **unguarded** (unlike the stripSuffix/img-rewrite callbacks which both have null guards at lines 1823/1908). **Result: the shop page rendered blank (0 bytes).** Fix: replaced the lazy `.*?` with an unrolled loop `[^<]*(?:<(?!card-start)[^<]*)*` (per-`<` stepping, same pattern already used for the stripSuffix fix at line 1813), and added a null guard on the assignment (`if ($enriched !== null) $buffer = $enriched`) plus a guard on the inner `preg_replace` result. Verified against real category HTML (180 cards, 1.9MB, works) and a faithful full-shop simulation (2.5MB, 1.15MB footer script, 180 permalinks emitted, no null). The fix is symmetrical to A2 (stripSuffix) and A2b (img rewrite) — the same pattern the codebase already established for the same backtack-limit problem. See `src/core/functions.php:1938-1977`.
  - Verified against the exact live card markup (playwright): every lightbox image anchor (`a.product-image[data-rel^="prettyPhoto"]`) now carries `data-product-permalink`; the product-title anchor (already linking to the product page) is left untouched. Edge cases pass: empty buffer, no-YITH card skipped, non-numeric `data-fragment-ref` skipped, ID 0 skipped, idempotent.

- [x] 7.6 (a.ppt CSS) WooCommerce's `prettyPhoto.css` only targets `div.ppt` (selector `div.ppt { color:#fff; display:none; }`). The JS converts `.ppt` to `<a class="ppt">`, so the selector stops matching and the link inherits default link styling (`color:rgb(51,51,51)`, `display:inline`), making it invisible on the dark lightbox background. Fix: added `.pp_pic_holder.pp_default a.ppt { display:block; color:#fff; font-weight:700; font-size:17px; }` via `wp_add_inline_style('woocommerce_prettyPhoto_css', …)` in `src/core/functions.php` (later moved to the "Simple Custom CSS and JS" plugin entry `2068.css` on prod). The repo source of truth is `src/features/lightbox/modal-custom.css`.
